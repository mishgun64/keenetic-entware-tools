# keenetic-entware-tools

Набор скриптов для Keenetic + Entware (aarch64): подготовка флэшки, первичная настройка роутера, установка nfqws2, доставка его конфигурации и загрузка списков доменов для маршрутизации через VPN.

| Скрипт                   | Где запускается      | Что делает                                                                                                                                                             |
|--------------------------|----------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `prepare-entware-usb.sh` | Linux-ПК             | Форматирует флэшку в ext4, кладёт Entware-инсталлятор в `/install`                                                                                                     |
| `setup-entware.sh`       | Роутер (Entware)     | SSH-ключ, пароль root, пакеты, алиасы, cron, nfqws2-keenetic                                                                                                           |
| `deploy-nfqws2.ps1`      | Windows (PowerShell) | Копирует `.\nfqws2` на роутер в `/opt/etc/nfqws2`                                                                                                                      |
| `add-domain-lists.ps1`   | Windows (PowerShell) | Загружает списки из `.\domain-lists` в `object-group fqdn` роутера, назначает маршрут через VPN (по умолчанию — интерфейс `awg*`, если он есть), прописывает DNS-серверы DoH и отключает DNS провайдера на ISP и PPPoE |
| `wg-manager.ps1`         | Windows (PowerShell) | Локально генерирует и ведёт конфиги WireGuard (сервер + клиенты) в `./<имя>`                                                                                            |

> Для воспроизводимости вместо `refs/heads/main` в ссылке можно указать хэш коммита.
> Скрипты выполняются от root: перед запуском по ссылке прочитай их.

## 1. Подготовка флэшки

Linux-машина, нужны `parted`, `e2fsprogs`, `curl` или `wget`. **Все данные на устройстве будут стёрты.**

```bash
sudo bash -c "$(curl -fsSL https://github.com/mishgun64/keenetic-entware-tools/raw/refs/heads/main/prepare-entware-usb.sh)" _ /dev/sdX ENTWARE
```

Скрипт скачивает `aarch64-installer.tar.gz` до форматирования, показывает `lsblk` и требует ввести имя устройства для подтверждения. Результат: ext4-раздел с меткой `ENTWARE` и файлом `/install/aarch64-installer.tar.gz`.

## 2. Первичная настройка роутера

Заходишь на роутер по SSH, ставишь curl и запускаешь:

```sh
opkg update && opkg install curl
sh -c "$(curl -fsSL https://github.com/mishgun64/keenetic-entware-tools/raw/refs/heads/main/setup-entware.sh)"
```

Форма `sh -c "$(...)"` нужна, чтобы stdin остался терминалом: скрипт спрашивает, менять ли пароль root, и вызывает `passwd`. Через `| sh` это не сработает.

Что делает скрипт:

1. Добавляет SSH-ключ в `/opt/etc/dropbear/authorized_keys`.
2. Спрашивает, нужно ли сменить пароль root.
3. Ставит `cron nmap neovim htop`.
4. Добавляет алиасы `v='nvim'` и `ll='ls -lh'` в `~/.profile`.
5. Создаёт `/opt/etc/cron.daily/opkg-upgrade` (ежедневный `opkg upgrade`).
6. Ставит `nfqws2-keenetic` и `nfqws-keenetic-web`.

Перед использованием замени в скрипте `SSH_KEY` на свой публичный ключ.

## 3. Списки доменов для маршрутизации через VPN

`add-domain-lists.ps1` скачивает файлы `*.txt` из папки [`domain-lists`](https://github.com/mishgun64/keenetic-entware-tools/tree/main/domain-lists) этого репозитория и создаёт по ним группы объектов `object-group fqdn` на роутере Keenetic, затем назначает DNS-маршрутизацию этих групп через выбранный VPN-интерфейс. Работает через HTTP API роутера (RCI), SSH не нужен. Требуется PowerShell 5.1+ и доступ к веб-интерфейсу роутера с ПК.

Запуск без скачивания файла (из любой папки):

```powershell
& ([scriptblock]::Create((irm https://github.com/mishgun64/keenetic-entware-tools/raw/refs/heads/main/add-domain-lists.ps1)))
```

Скрипт, выполняемый из памяти, не блокируется политикой выполнения PowerShell. Списки берутся прямо из репозитория (ветка `main`, через GitHub API), локальная папка `domain-lists` не нужна. Репозиторий должен быть публичным, а у GitHub API без токена лимит 60 запросов в час на IP.

Что спрашивает скрипт:

1. Роутер из списка (`192.168.47.1` … `192.168.51.1`) или IP вручную.
2. Логин (по умолчанию `admin`) и пароль.
3. VPN-интерфейс. Перед вопросом скрипт печатает список интерфейсов роутера (с описаниями) и подсказывает имя в приглашении; список читается после авторизации через `show/interface`, при ошибке выводится предупреждение и скрипт продолжает работу.
   - если среди интерфейсов есть имя, содержащее `awg` (AmneziaWG), оно помечается `<- default` и подставляется при пустом вводе (`Enter = awgX`);
   - если `awg` нет — пустой ввод означает, что маршруты не назначаются, создаются только группы.
4. DNS-серверы DoH, которые нужно прописать (см. ниже).

Формат файлов в `domain-lists/`:

- одна запись на строку: домен, IPv4/IPv6-адрес или подсеть в формате CIDR (`149.154.164.0/22`);
- `#` начинает комментарий, пустые строки и дубликаты игнорируются, префикс `*.` отбрасывается;
- имя файла становится описанием группы (`music.txt` → `description music`), суффикс `_ipv4` / `_ipv6` отбрасывается (`telegram_ipv4.txt` → `telegram`).

Поведение:

- Группа называется `domain-listN` (первый свободный номер). Если на роутере уже есть группа с таким описанием, она дополняется, а не создаётся заново, поэтому повторный запуск безопасен.
- Скрипт только добавляет записи. Удалённые из файла домены на роутере остаются.
- Маршрут назначается командой `dns-proxy route object-group domain-listN <интерфейс> auto`.
- При первой же ошибке роутера скрипт останавливается без сохранения конфигурации. В конце выполняется `system configuration save`.

### DNS-серверы DoH (DNS-over-HTTPS)

Скрипт предлагает меню и прописывает выбранные серверы в секцию `dns-proxy` роутера:

| № | Сервер     | Адрес                                  |
|---|------------|----------------------------------------|
| 1 | quad9      | `https://dns.quad9.net/dns-query`      |
| 2 | google     | `https://dns.google/dns-query`         |
| 3 | cloudflare | `https://cloudflare-dns.com/dns-query` |
| 4 | все сразу  | 1, 2, 3                                |
| 5 | пропустить | Enter                                  |

Ввод принимает номер, список через запятую/пробел (`1,3`), `4`/`all` или пустое значение.

Поведение:

- **Сначала очищаются все ранее прописанные DNS-серверы** в секции `dns-proxy`, только потом добавляются выбранные — это режим замены, а не дополнения. При пропуске (пункт 5) ничего не меняется.
- Запись добавляется командой `https upstream <url> dnsm`, где `dnsm` — формат ответа KeeneticOS, а не произвольное имя.
- Удаление перебирает несколько вариантов синтаксиса `no` (`no <строка из конфига>`, `no https upstream <url> dnsm`, `no https upstream <url>`, `no upstream <url>`, в том числе однострочную форму `dns-proxy no …`), потому что синтаксис отличается между версиями прошивки.
- Если ни один вариант не принят, секция `dns-proxy` пересобирается заново (`no dns-proxy` + повторное создание) с сохранением `rebind-protect`, `route` и `filter`.
- Результат проверяется перечитыванием `running-config`, а не по статусам RCI: статусы не совпадают с отправленными командами, так как вход в контекст `dns-proxy` не возвращает своего статуса.
- При любой ошибке скрипт останавливается, `system configuration save` не выполняется.

### Отключение DNS провайдера

После настройки DoH скрипт прописывает `ip no name-servers` в WAN-интерфейсы, чтобы провайдерский DNS не использовался:

- интерфейс с `rename ISP` (если такого нет — интерфейс с именем `ISP`);
- интерфейс `PPPoE0` (любой `PPPoE`/`PPPoE1`…), если он есть в конфигурации.

Поведение:

- Обрабатывается каждый найденный интерфейс отдельно: если команда уже есть, ничего не меняется (повторный запуск безопасен).
- Несуществующие интерфейсы пропускаются с предупреждением: например, если PPPoE не настроен, скрипт не падает.
- Отключение выполняется **только** при наличии хотя бы одного DoH-upstream: без рабочего резолвера роутер остался бы без DNS, поэтому в этом случае шаг пропускается с предупреждением.
- Если команда не применилась на существующем интерфейсе — остановка без сохранения конфигурации.

## 4. Конфиги WireGuard

`wg-manager.ps1` создаёт и ведёт конфигурации WireGuard **локально**: серверный `server.conf` с пирами клиентов и по файлу `<имя>.conf` (плюс `<имя>.png` с QR-кодом) на каждого клиента. На роутер и на VPN-сервер он ничего не применяет — готовый `server.conf` выкладывается отдельно.

Нужен `wg.exe` (WireGuard for Windows) в `PATH` — либо путь в `-WgPath`. Файлы пишутся **в текущий каталог**, в подпапку с именем сервера:

```
<текущий каталог>/
└── wg-home/                 # имя сервера (аргумент <server>)
    ├── server.conf          # серверный конфиг, [Peer] на каждого клиента
    ├── ivan.conf            # клиентский конфиг
    ├── ivan.png             # QR-код клиента (PNG)
    ├── oleg.conf
    └── oleg.png
```

Клиентские файлы лежат **в той же папке**, что и `server.conf`.

Побочных `.json` и `server.base.conf` нет: параметры профиля (endpoint, DNS, AllowedIPs клиентов) хранятся комментариями `# wg-manager: …` в `server.conf`, а список клиентов — это `.conf`-файлы в папке сервера.

### Интерактивное меню

Без аргументов скрипт показывает диалог: что сделать дальше. Это основной режим при ручной работе.

```powershell
& ([scriptblock]::Create((irm https://github.com/mishgun64/keenetic-entware-tools/raw/refs/heads/main/wg-manager.ps1)))
```

```
What do you want to do?
  1) create server
  2) add client
  3) list clients
  4) show client config
  5) export client path
  6) remove client
  0) exit
```

Меню работает циклично: после действия возвращается к списку (перед этим ждёт Enter), `0`/`q` — выход. Сервер и клиент можно выбрать номером или именем, `b` — назад. Ошибки выводятся в меню и не прерывают работу.

Значения по умолчанию при создании сервера (Enter принимает их):

| Вопрос | По умолчанию |
|---|---|
| Server name | `wg-home` |
| Endpoint host | (обязательно), только хост без порта |
| Listen port | `51820` |
| Server address | `10.10.0.1/24` |
| DNS for clients | адрес сервера (`10.10.0.1`) |
| Client AllowedIPs | `0.0.0.0/0` |

### Запуск одной командой с параметрами

То же самое без меню, если нужно сразу выполнить конкретную операцию (например из другого скрипта):

```powershell
& ([scriptblock]::Create((irm https://github.com/mishgun64/keenetic-entware-tools/raw/refs/heads/main/wg-manager.ps1))) server init wg-home -Endpoint vpn.example.com
```

```powershell
& ([scriptblock]::Create((irm https://github.com/mishgun64/keenetic-entware-tools/raw/refs/heads/main/wg-manager.ps1))) client add wg-home ivan
```

Команды:

| Команда | Что делает |
|---|---|
| `server init <server> -Endpoint host` | Создаёт `./<server>/server.conf` (ключи генерирует `wg genkey`/`pubkey`) |
| `client add <server> <client>` | Новый клиент: ключи, PSK, свободный IP из подсети сервера, `<client>.conf` и `<client>.png` в папке сервера, пир в `server.conf` |
| `client list <server>` | Таблица клиентов: имя, адрес, Enabled/Disabled |
| `client show <server> <client>` | Показывает клиентский конфиг |
| `client export <server> <client>` | Печатает полный путь к файлу клиента |
| `client remove <server> <client>` | Удаляет клиента и его `.png` (с подтверждением `YES`) |

QR-код клиента создаётся автоматически при `client add` файлом `<client>.png` рядом с конфигом. В терминал он не выводится — встроенный генератор не требует `qrencode` или других внешних программ.

Параметры `server init`: `-Address 10.10.0.1/24`, `-ListenPort 51820`, `-DNS 10.10.0.1`, `-ClientAllowedIPs "0.0.0.0/0"`. `-DNS` по умолчанию берётся из адреса сервера.

`-Endpoint` принимает **только хост** (`vpn.example.com`): порт для клиентского `Endpoint` берётся из `-ListenPort`. Если всё же указать `host:port`, этот порт будет использован и как `ListenPort`. Адрес клиента выдаётся автоматически из подсети сервера (поддерживаются IPv4-префиксы `/16`–`/30`). Каталог хранения можно переопределить через `-Root`, путь к `wg.exe` — через `-WgPath`.

Перед каждой перезаписью `server.conf` рядом сохраняется резервная копия `server.conf.<дата>-<время>.bak`.
